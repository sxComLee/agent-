# 笑川：【深度聊】Moltbot：正在改写AI创业者和Agent产品的底层范式

> 作者：笑川（笑川AI进化论）
> 原文链接：https://mp.weixin.qq.com/s/4Yp-aYUz...

## Peter Steinberger其人

- 少年时期：偷学校游戏盘，自写防拷贝程序卖钱
- 上大学全职工作，啃MFC技术书
- 被约会App的烂前端气到 → 地铁上自己写App，第一个月赚1万美金
- 做PDF渲染13年，做出PSPDFKit，跑到10亿设备上
- 公司70+人全远程，卖掉股份，burnout三年
- Claude Code/Codex出现 → 重燃折腾劲儿
- 顺手做了Clawdbot，GitHub Star一直涨

## 创业者范式的转变

### 旧范式：我来写代码

### 新范式：我搭系统 + 写说明书 + 让AI写代码

> "他的工作内容要被重塑"不在于他Have AI，而在于他很自然地接受了这件事。

### 关键动作

他不懂Web开发，没去报班学React/Next.js，而是：
1. 把1.3MB的GitHub文档扔给Gemini → 写specification
2. 把说明书扔给Claude Code → 说"build"
3. 点"继续、继续、继续"

> "这对我来说已经足够了，我看到的是一个'工作方式会被重写'的未来"

### 视角转变

从：
- 盯每一行代码的细节
- 关心行数和变量名

到：
- 盯**架构、接口、边界**
- 关心**系统结构、技术债、可扩展性、模块化**

## Moltbot的产品定位

不是"聊天机器人"，也不是"工作流机器人"，而是：

> "把整个电脑当成一个可以被脚本控制的世界，把Agent放在这个世界的最中心位置"

Agent每次问自己：
- 要不要开终端跑CLI？
- 要不要看一个文件头？
- 要不要转一下格式？
- 要不要调一个云服务？
- 要不要写个新脚本再跑一遍？

→ 它是**个人DevOps + RPA + 助理**的混合机

## Prompt Request的创新

### 什么是Prompt Request

看一个改动，不看PR里的代码diff，而是看**生成这些代码的prompt是什么**。

> 你别先写代码，先写一份尽可能详细的Prompt Request，把需求背景、边界条件、预期行为、失败情况、兼容性要求都写清楚。

### 为什么重要

把原来"藏在资深工程师脑子里"的东西强行拉到文本层面、显性化：

**之前**：靠经验直觉的暗号（"你照着上一个接口那样搞"）
**之后**：能被语言模型读懂的说明书

### 收益

- 人可以下线，Agent按说明书继续工作
- 说明书沉淀下来，团队少人也能接手
- 版本回溯更容易：知道"基于什么假设生成的"

### 对产品思路的启示

做Agent产品：
- 不只是"更智能的IDE"
- 而是"帮团队建立Prompt Request规范和协作机制"

## 国内落地路径

直接把电脑交给Agent → 国内企业不可能接受。

**但可以这样：**

不从OS权限入手，从**业务闭环**入手：

1. 选择清晰的业务域（电商运营/跨境广告/客服/合同审核等）
2. 把所有内部系统、API、数据库拼成"**虚拟工作台**"
3. 让Agent在工作台上运行：查数、写草稿、触发动作、建任务

特点：
- 权限边界清晰，安全可控
- 内部自动化程度高
- 效果可以用钱算出来

## 给个人的行动建议

### 第一步：区分清单

把最近复杂的工作拆成：
- **清单A**：哪些环节可以丢给Agent先试？
- **清单B**：哪些必须自己看一眼才放心？

### 第二步：写说明书练习

假设让Agent写周报 → 先把"什么算好、哪些数字必须有、哪里不能瞎编"写下来。

### 第三步：参与闭环搭建

主动去争取搭：自动化测试、日志回溯、完整业务链路梳理。

**关键转变**：从"只在聊天框里问问题"→"参与设计Agent出手的边界和验证机制"
