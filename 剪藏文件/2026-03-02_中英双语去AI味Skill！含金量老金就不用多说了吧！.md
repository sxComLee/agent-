这个项目叫 Humanizer，目前7200多星。 更重要的是，中文版也有了，3300多星。

## 为什么AI写的东西一看就假

不是你用的模型不行，是所有大模型都有同一个毛病。

维基百科的解释很精准：

"LLMs use statistical algorithms to guess what should come next. The result tends toward the most statistically likely result that applies to the widest variety of cases."

翻译一下：

大模型的本质是"猜下一个词"。

猜的结果，天然就是最保险、最通用、最没有个性的那个选项。

这就是为什么所有AI写出来的东西都长得差不多。

不是某个模型的问题，是这类技术的底层限制。

具体到中文写作，老金我总结最常见的三类"AI味"。

第一类：AI词汇泛滥

"此外"、"至关重要"、"深入探讨"、"充满活力"、"不断演变的格局"。

这些词在2023年之后的文本里出现频率暴增，已经成了AI写作的标志性词汇。

正常人写东西不会动不动就"此外"，更不会说"不断演变的格局"。

第二类：假大空的修饰

"坐落于风景如画的XX"、"拥有丰富的文化底蕴"、"令人叹为观止的设计"。

AI特别喜欢往上堆形容词，把一句简单的话写得像旅游宣传册。

第三类：万能结尾

"让我们拭目以待"、"未来可期"、"这代表了向正确方向迈出的重要一步"。

这类结尾没有任何信息量，纯粹是因为模型不知道怎么收尾，就用了一个"最安全"的表达。

这三类加起来，基本上就是AI文章被一眼看穿的原因。
## 维基百科总结的24种AI痕迹

WikiProject AI Cleanup是维基百科的一个专项清理团队，专门处理AI生成的垃圾内容。

他们从上万篇AI生成文本中总结出24种规律性痕迹，分成4大类。图没提交成功，放留言区域了。

老金我挑几个中文场景最常见的展开说。

夸大意义

AI特别喜欢给普通事实加上宏大叙事。

改写前：加泰罗尼亚统计局于1989年正式成立，标志着西班牙区域统计演变史上的关键时刻。

改写后：加泰罗尼亚统计局成立于1989年，负责收集和发布区域统计数据。

看到了吗？

"标志着"、"关键时刻"、"演变史"——全是AI加上去的修饰，原本的事实就是"成立了，干统计的"。

系动词回避

AI不喜欢用"是"和"有"，它觉得太简单了，非要换成"作为"、"充当"、"拥有"。

改写前：Gallery 825作为LAAA的当代艺术展览空间。画廊设有四个独立空间。

改写后：Gallery 825是LAAA的当代艺术展览空间。画廊有四个房间。

"作为"换成"是"，"设有"换成"有"。简单直接，反而更像人说的话。

否定式排比

"不仅仅是X，而是Y"这个句式，AI用得比人类多得多。

改写前：这不仅仅是一次更新，而是我们思考生产力方式的革命。

改写后：软件更新添加了批处理、键盘快捷键和离线模式。

"不仅仅是...而是..."直接砍掉，换成具体功能描述。信息量更大，AI味消失。

三段式法则

AI特别喜欢把东西凑成三个一组。 "无缝、直观和强大"、"创新、灵感和洞察"、"速度、质量和采用率"。

真实的人类写作不会刻意凑三个。有时候两个就够了，有时候需要四个，不用硬凑。
## Humanizer是什么

了解了24种痕迹之后，问题来了：每次写完都要对着清单自查，太累了。

GitHub用户 blader 把这24条规律做成了一个Claude Code Skill。

装上之后，你只要说一句"humanize这段文字"，它就会自动扫描所有24种模式，然后帮你重写。

项目地址：https://github.com/blader/humanizer

目前7200多星，MIT协议开源。

核心机制 Humanizer的处理流程分三步。

第一步：扫描你的文本，识别所有24种AI写作痕迹。

第二步：重写有问题的部分，保留核心信息，去掉AI味。

第三步：做一轮"反AI审计"——它会问自己"这段文字还有什么地方明显是AI写的"，然后再改一遍。

这个两遍重写的设计很聪明。

第一遍去掉明显的AI模式，第二遍抓住残留的痕迹。

相当于请了一个编辑帮你改两遍稿。

不只是去味，还要加"人味"

Humanizer不光删坏模式，还会主动注入真实感。

它的SKILL.md里专门有一节叫"Personality and Soul"（个性与灵魂），核心观点是：

干净但没有灵魂的写作，跟AI写的一样明显。

它会建议你：

有观点，不要只报告事实，要对事实做出反应。

变化节奏，长句短句交替使用。

承认复杂性，"这令人印象深刻但也有点不安"比"这令人印象深刻"更像人话。

适当使用"我"，第一人称不是不专业，而是诚实。

这个思路跟老金我写公众号的理念完全一致。

去AI味只是及格线，有人味才是满分。
## 中文版也来了

原版Humanizer的SKILL.md是全英文的。

如果你的写作场景是中文，英文模式匹配的效果会打折扣。

好消息是，GitHub用户 op7418 做了一个完整的中文汉化版。

项目地址：https://github.com/op7418/Humanizer-zh

目前3300多星。

汉化版做了什么

不是简单的机翻，而是做了中文场景的适配。

24种模式的描述全部翻译成中文。

每种模式都加了中文的改写前/改写后对比示例。

针对中文不适用的模式（比如标题大小写）做了标注说明。

比如"AI词汇"这个模式，英文版列的是"Additionally"、"crucial"、"delve"。

中文版对应的是"此外"、"至关重要"、"深入探讨"。

再比如"宣传式语言"，英文版的例子是"nestled within the breathtaking region"。

中文版改成了"坐落在风景如画的杭州市中心，这家咖啡馆拥有丰富的文化底蕴和令人叹为观止的装饰"。

一看就知道在说什么，不用脑补英文语境。

额外功能：质量评分

汉化版还加了一个质量评分系统，从5个维度给改写后的文本打分。图没提交成功，放留言区域了。

总分50分，45分以上算"去味成功"。

这个评分功能原版没有，是汉化版的独有加分项。

如果对你有帮助，记得关注一波~
## 怎么安装

两个版本的安装方式都很简单。

英文原版

```
mkdir -p ~/.claude/skills
```

```
git clone https://github.com/blader/humanizer.git
```

```
~/.claude/skills/humanizer
```

中文版（推荐）

```
npx skills add https://github.com/op7418/Humanizer-zh.git
```

如果你更喜欢手动安装：

```
git clone https://github.com/op7418/Humanizer-zh.git
```

```
~/.claude/skills/humanizer-zh
```

装完在对话中输入 /humanizer 或 /humanizer-zh 就能激活。 也可以直接说"帮我人性化这段文字"或"humanize this text"，Skill系统会自动匹配。

安装后的目录结构

```
~/.claude/skills/humanizer-zh/
```

```
├── SKILL.md       # 技能定义文件（中文版，核心）
```

```
└── README.md      # 说明文档
```

就两个文件，零依赖，装完就能用。
## 实测：改写前vs改写后

光说原理没用，老金我直接拿一段典型的AI文章测一下。

改写前（AI味十足）

新的软件更新作为公司致力于创新的证明。此外，它提供了无缝、直观和强大的用户体验——确保用户能够高效地完成目标。这不仅仅是一次更新，而是我们思考生产力方式的革命。行业专家认为这将对整个行业产生持久影响，彰显了公司在不断演变的技术格局中的关键作用。

改写后（人性化）

软件更新添加了批处理、键盘快捷键和离线模式。来自测试用户的早期反馈是积极的，大多数报告任务完成速度更快。

老金我来拆解一下改了什么。

"作为公司致力于创新的证明"——夸大意义，删。

"此外"——AI词汇，删。

"无缝、直观和强大"——三段式法则+宣传语言，删。

破折号+"确保"——肤浅的-ing分析变体，删。

"不仅仅是...而是..."——否定式排比，删。

"行业专家认为"——模糊归因，删。

"不断演变的技术格局"——AI词汇组合拳，删。

一段4行的废话，变成了2行有信息量的事实。

这就是Humanizer干的事。
## 老金的使用建议

装中文版就够了

如果你主要写中文内容，直接装中文版。

中文版包含了原版的所有24种模式，还加了中文适配和质量评分。

英文版和中文版不冲突，都装也行，按需调用。

不要把它当"反AI检测器"

Humanizer的核心价值不是骗过AI检测器，而是真正提升写作质量。

它教你的是"好的写作应该是什么样的"——直接、具体、有节奏、有观点。

这些原则不管AI不AI，都适用。

配合Claude Code的记忆系统效果更好

装了Humanizer之后，Claude Code会记住你的去味偏好。

比如你反复告诉它"不要用此外"，它的MEMORY.md会把这条记下来。

几次之后，Claude生成的初稿就会自动避开这些AI词汇，连去味这一步都省了。

学会自查清单

就算不装Skill，知道这24种模式本身就很有价值。

写完文章之后，自己扫一遍：有没有"此外"？有没有三段式凑数？结尾是不是"让我们拭目以待"？ 这种意识一旦建立，你的写作质量会有质的提升。
